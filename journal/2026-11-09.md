## Round 2 — lifecycle, CI that talks back, release as a product

- `meta` grew `id` (UUID), `version`, `modified`, `status`, `mitre_attack`; promotion gate
  (`blocking` needs `stable` + `confidence = high`); uniqueness across the repo.
- CI: `report.py` on head and base, `diff_report.py` as a PR comment (new/removed hits per rule,
  time per rule with Δ%, fixture changes), corpus manifest to tell runner drift from FP.
- `tests/samples.lock` + a manual MalwareBazaar job that downloads, scans, deletes.
- Release: bundles per purpose, `.yarc`, CHANGELOG, SHA256SUMS, cosign keyless, YARA 4.x matrix.
- Code quality: pytest, ruff, mypy strict, bandit, pip-audit, pre-commit, Dependabot.

Decisions, and why:

- **`mitre_attack` is a string, not a list.** YARA meta has no list type. It is `"T1055.002, T1027"`
  or `"none"`, and the lint validates each item. Wishing otherwise would not compile.
- **No invented hashes.** `samples.lock` shipped empty. FamilyX is fictional; a made-up sha256 in a
  lock file is a lie that looks like data. The seed hash in the example rule is a visibly marked
  placeholder (the md5 of the empty string) with a comment telling you to replace it.
- **Bandit instead of Semgrep.** Either was acceptable. Bandit has no registry or network dependency
  on the runner, so a CI run cannot fail because a rules feed was unreachable. Aikido stays pending:
  it needs an interactive login that a headless session cannot do, and the README says so.
- **Time per file, not per rule.** The bindings expose no per-rule profiling, so each rule file is
  compiled alone and timed. With one rule per file it is the same number.

### Incident: the `git checkout` that reverted the working tree

While simulating the CI locally (base vs head), the session ran
`git --work-tree=/tmp/base checkout main -- .` to export `main` into a temp dir, then a plain
`git checkout -- .` meant to "clean up". The first command updated the **index** to `main`'s
contents; the second then restored every tracked file in `/workspace` from that index. All of the
round's edits to tracked files (`yrlib.py`, `lint_rules.py`, `hunt.py`, `scan_goodware.py`, the
rule, the template, Makefile, CI config, docs) were overwritten with the first commit's versions.
New untracked files survived.

Recovery: nothing had been committed yet, so there was no reflog to lean on. The files were rebuilt
from the session's own edit history (the full-file writes and each patch applied on top, in order),
then the entire verification pass was rerun (lint, fixtures, ruff, mypy, pytest, bandit, bundles,
goodware scan, CI simulation) before the first commit of the round. Round 3 opened with an
integrity audit for exactly this reason: clean tree, HEAD == origin, every file the round-2 report
cited present with the expected content. Nothing was missing.

Lesson, kept: never `git checkout -- .` on a tree with uncommitted work, and never combine
`--work-tree` exports with anything that touches the index. Commit early, in small logical commits;
the lack of a commit was the whole exposure.

## Round 3 — a tool nobody has ready

- **(a) `tools/anchors/`**: capstone superset disassembly, wildcards only on operands that vary
  (disp32, rel8/rel32, immediates) using capstone's operand offsets, never on opcodes; k-of-N,
  suffix suppression, subsumption, overlap NMS, filler trimming, goodware filter, ranking.
  Acceptance: from the two synthetic decoder builds it returns the hand-written `$decode`
  byte for byte (`48 8B 0D [4] 48 85 C9 74 ?? 0F B6 01 34 ?? 88 01 48 FF C1`). First version took
  2m52s on `/bin/ls`; slicing `blob[start:]` per start was O(n²). Windowed decoding brought it to
  ~3 s. No Ghidra wrapper: Ghidra is not installed here, and a wrapper that was never run is
  not a deliverable.
- **(b) `scope`**: `file | memory | both`; the lint rejects `uintN(0)`, `filesize` and `pe.*` in
  memory rules. `rules/memory/MAL_Win_Loader_FamilyX_InMemory.yar`. `scripts/memscan.py` compiles
  only memory rules; raw backend in overlapping chunks, Volatility 3 backend for real images, auto
  fallback. Tested on a synthetic dump (random bytes, artifacts in the middle). The vol3 happy
  path was not exercised end to end: there is no real memory image in the repo, by rule.
- **Coverage panel**: `docs/coverage.md` generated from `meta`; the CI fails if stale. The
  "experimental > 90 days" list uses age bands (90/180/365/730) so the file does not change every
  morning, and `--check` ignores the reference-date line.
